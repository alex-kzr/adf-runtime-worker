# Host runtime development

## Boundaries

`models.py` contains immutable adapter requests/results and the structural `Adapter` protocol. `adapters.py` maps pinned provider JSONL fixtures to bounded normalized events. `process.py` owns argv-based processes, pipes, deadlines and group termination. `security.py` owns canonical roots, restricted environment and pre-storage redaction. `journal.py` owns fsynced atomic intents and OS locks. `git_workspace.py` owns allocation, exact-tree staging/commits and serial delta integration. `executor.py` exposes only registered runtime phases. `client.py` is the scoped API facade. `supervisor.py` owns one execution independently of the transport consumer. `service.py` consumes Redis and acknowledges only persisted terminal/no-op delivery. `telemetry.py` exports opt-in metadata-only OTel.

## Ownership and recovery

Operator-selected persistent profiles are carried in `worker_config.provider_profiles`, separately from immutable agent/job input. `profiles.py` validates existing canonical owned Linux home directories with mode 0700 and refuses job/worktree overlap. Probe and provider launch use the same fixed `CODEX_HOME` or `CLAUDE_CONFIG_DIR` selector; default profiles retain the stable Linux HOME. No credential contents, login flow, OAuth-token variable or copied per-job cache is involved. Ordinary job environment rules remain unchanged. Claude continues its supported persistent CLI profile without automatically generating a token. A shared Codex app-server requires separate thread-close ownership proof; a common directory alone does not solve parallel refresh ownership.

[Doctor requires explicit operator profile selection](doctor-profiles.md) before invoking a native CLI. Its `--codex-home`/`--claude-config-dir` paths use the same validator; omitted profiles report `PROFILE_REQUIRED` without a native probe. This prevents diagnostics from silently inspecting a default auth store after shell selectors are stripped. Runtime/job environment permissions and the shared ancestor guard remain unchanged.

The consumer registers a stable UUID stored under the worker root, claims an immutable execution snapshot from API, fsyncs a supervisor ticket, then spawns a detached Python supervisor. The supervisor holds one process slot and a target worktree lock, journals its own identity and every active CLI/Git child PID, start ticks, group and session before writing. The immutable API heartbeat identity is the supervisor plus journal ID; sequential checks do not replace it with child PIDs. The supervisor synchronously binds that identity with a valid heartbeat before any Git/provider operation. It polls control every second and renews the lease every ten seconds; a five-second safety margin stops a CLI before the locally computed lease expiry. Each launched CLI/Git process owns a dedicated Linux session. TERM gets ten seconds, followed by bounded KILL, across all live session members even when a bundled tool host creates a separate process group. Normal provider exit gets the same bounded EOF shutdown grace within the original execution deadline. Signals use pidfds plus checked PID/start-tick/session identities; incomplete, recycled or unsupported identities keep the result uncertain. Cancellation never claims stopped when cleanup could not be proved. The journal retains every launched session and terminal provider identity, so a later Git command cannot erase an unresolved CLI host. CPython builds without standard pidfd bindings use fixed Linux syscall wrappers only on verified 64-bit x86_64/aarch64 ABI, propagate kernel errno and fail closed without a PID-kill fallback. This is needed by the pinned uv Python 3.12.9 build; it does not require named libc pidfd wrappers, installation or host configuration changes. ABI numbers come from the official Linux [x86_64 table](https://github.com/torvalds/linux/blob/v6.8/arch/x86/entry/syscalls/syscall_64.tbl) and [asm-generic table](https://github.com/torvalds/linux/blob/v6.8/include/uapi/asm-generic/unistd.h), used by [arm64](https://github.com/torvalds/linux/blob/v6.8/arch/arm64/include/uapi/asm/unistd.h).

A consumer restart does not terminate its supervisors. They continue renewing and persisting results; Redis XACK requires an API-confirmed terminal result marker. Persisting `uncertain` alone never permits acknowledgement; the stopped supervisor/group and reacquired worktree lock must first receive terminal reconciliation. DB epochs fence API writes, **not** live filesystem writes. Startup reconciliation refuses a live supervisor/group or held worktree lock. Dead proof includes the same journal/owner/epoch and reacquired OS lock; uncertain executions become failed/cancelled through the API rather than blindly launching a second writer. A kill during the tiny spawn-to-child-identity window remains uncertain if the inherited worktree lock is held; operator recovery is required if identity cannot be proved. No process death is inferred from elapsed time.

Event IDs and per-epoch sequence are fsynced before API ingestion. Terminal results are journaled before publication. Restart replays unsent durable events and the exact terminal intent before claiming; an abandoned execution without a result is reconciled, never relaunched under the same ID. Exact immutable event/result bodies are reused during bounded transient retries. Auth/policy/stale lease failures are permanent; provider retries are owned by the orchestrator. Poison transport messages are acknowledged only after the API persists a sanitized dead-letter record.

## Git and validation

Only trusted, canonical ext4 projects are eligible. Nested target submodules, Git config includes, executable merge/diff drivers, fsmonitor, credential commands, filters, active hooks and required signing are rejected until separately verified policy support exists. The source checkout's dirty files/default branch are preserved. Allocation creates `factory/task/<task>/<execution>` with one unique write worktree; dependencies are applied to an isolated snapshot before recording its actual execution base and dependency completion marker. A crash between dependency deltas replays recorded completed intents and only the remaining immutable deltas. The root base stays separately pinned.

Development emits changes without committing. Registered checks bind the staged tree. Stable agent-definition IDs, rather than configuration-version IDs, establish independent developer/reviewer identities; immutable version IDs are retained separately. A separate reviewer identity runs in read-only mode and returns schema-validated approval/findings; the worker binds it to the exact tested tree. Commit consumes trusted local journal evidence, validates approved paths and scans staged content, fsyncs parent/tree/trailer intent, then discovers a matching commit after a crash instead of committing twice. Git operations are serialized by project locks with guarded 100 ms contention polling. Every Git mutation checks cancellation, lease safety and the authoritative whole execution `deadline_at`; subprocess output is streamed into a bounded queue and capped at 20 MiB before further accumulation. Registered checks retain their separate `project.check_timeouts`, bounded by the whole execution deadline. Cancelling during commit retains any actual commit as evidence but returns cancellation.

Integration sequentially applies task deltas to `factory/integration/<run>`, starts from the pinned root with no generic predecessor application, journals each integration source/parent/prepared tree and commit, runs registered combined checks and leaves main unchanged. A conflict preserves the worktree and pauses for manual resolution. Resume requires the original integration allocation and a human-approved clean exact `resolution_tree_sha`; it does not reapply conflicted deltas. Optional autonomous repair is not enabled. Test/review repairs copy only scanned, approved source changes into a fresh attempt worktree on the same dependency tree; the old attempt remains evidence.

## Provider policies and residual trust

Codex 0.157.0 uses noninteractive JSONL, `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, approval `never`, and read-only/workspace-write sandbox. Network is disabled for model shell execution. User MCP configuration is excluded. Compiled apps/browser/computer/image/hook/plugin/remote-plugin features are explicitly disabled. Unapproved native skills are disabled through exact path selectors; host discovery is enabled only while materializing the explicit approved catalog. Automatic dependency installation and web search are disabled. Codex cannot promise a per-command shell allowlist through this adapter; trusted development is a coarse worktree sandbox grant. Codex supports a narrow MCP tool catalog through verified 0.157.0 `mcp_servers.<name>.enabled_tools`, `required`, `startup_timeout_sec` and `tool_timeout_sec` configuration. `--strict-config` rejects unsupported configuration. The supported filesystem scope is the ADF-owned `adf.scoped-files.v1` stdio contract below. Its MCP tool allowlist is separate from the coarse built-in worktree/shell profile; it does not promise a shell command allowlist. Unsupported built-in mappings and generic server scope contracts fail without silently expanding rights. Login shells are disabled to avoid inheriting profile setup. The pinned bundled code-mode host remains enabled per invocation: it executes the CLI tool runtime, including assigned MCP tools, while `daemon_auto_start=false` prevents automatic persistent-daemon startup. Disabling this host made an actual native trial finish conversationally without running tools or changing files; the registered check then failed. This setting does not expand the MCP registry or change the sandbox, authentication or global configuration. The pinned upstream [availability handling](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/core/src/tools/code_mode/mod.rs) fails closed for code-mode models without this host; its [execute handler](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/core/src/tools/code_mode/execute_handler.rs) passes the enabled nested tool specifications to the runtime.

The [2026-10-10 native capability evidence](../../../docs/evidence/codex-scoped-capabilities-2026-10-10.json) records a fresh offline worker trial using the existing Codex subscription: approved native skill materialization, the exact owned `factoryfiles.read_marker` MCP call, hidden synthetic stamp and marker digest checks, independent review, commit and integration all passed. Both observed bundled hosts used a distinct process group inside the owned CLI session; retained-session death and target OS-lock reacquisition were checked after completion. The earlier fourth fixture passed development/checks but correctly stopped at rejected review because its reviewer received incomplete task/check context. The final fixture supplied the same immutable task, expected digests and tested-tree/check evidence, with the same read-only approved skill/MCP catalog. This corrects the offline harness context; it does not change review policy or retry a previous snapshot. Artifact identifiers in this evidence are local SHA256 identifiers from a fsynced Ledger test double. This trial does not exercise deployed API/Redis dispatch; that acceptance gate remains pending.

Claude Code 2.1.296 uses `--restricted`, `--safe-mode`, empty setting sources, disabled hooks/skills, strict explicit MCP configuration, an explicit built-in/permission tool list and unattended permission prompts `none`. The installed `--restricted` mode confines file tools to working directories and rejects bypass. Unscoped Bash, child agents and network tools are forbidden; explicitly bounded `Bash(...)` rules are allowed only in trusted development. Safe-mode's explicit MCP interaction still requires live verification before claiming scoped MCP readiness. `--bare` is deliberately absent because installed help says it skips OAuth/keychain authentication, which conflicts with subscription use. No dangerous skip-permissions flag, paid fallback, login automation or credential copying is implemented.

Worktrees and CLI permission profiles are not a complete hostile-code sandbox. Checks execute trusted project code as the worker's Linux user. Linux group privileges and the dedicated-account requirement remain deployment acceptance gates; a non-root process alone does not prove minimal privilege. The Windows host CLI is not substituted for a missing WSL provider. Financial cost remains null/unknown for subscriptions; numeric tokens are provider-reported, not estimates. The worker cannot impose a guaranteed financial cap. Claude API-equivalent `total_cost_usd` is preserved only as `provider_estimated_cost_usd`; it never becomes billed subscription cost or a financial limit. Numeric usage counts remain numbers through local/API redaction; malformed provider counts become unknown.

Worker bearer and Redis credentials are read only from the explicitly configured infrastructure secret files. Their values join the in-memory redactor before any local JSONL event, terminal journal or uploaded artifact; provider credential stores are never read or copied by the worker. Changed content is scanned for these known values before staging. Artifact IDs derive deterministically from execution/kind/content hash so transient retries reuse the same record.

No prompt, code, stdout, tool arguments, credential or exception description is exported to telemetry by default. Set `ADF_TELEMETRY_ENABLED=true` and `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://127.0.0.1:4318/v1/traces` for bounded metadata-only OTel. Collector holds Langfuse credentials. Export failure is nonfatal; eligible fixed spans contain correlation IDs and continue the job's W3C traceparent. Completed provider tool events emit fixed `tool.call` spans without arguments; provider event timing is not treated as verified tool duration.

The immutable API tool registry supplies provider mappings, not registry UUIDs as CLI tool names. Developer file writes can explicitly add `Edit`/`Write` with a write permission. ## Approved instruction skills and scoped MCP

Skills are instruction-only native Codex skills for this MVP. Store each approved `SKILL.md` under `<worker-root>/skills/<name>/`, with `name` and `description` frontmatter, and register its exact SHA-256. The worker checks canonical paths, symlinks, bounded UTF-8 content and known secrets before reading. Scripts, assets and `agents/openai.yaml` dependencies are not copied or executed under this contract. Hashing SKILL.md does not authorize unhashed adjacent files.

The adapter temporarily materializes only approved bytes in the allocated worktree's `.agents/skills/<name>/SKILL.md`. Native `skills.config` enables those exact paths and disables unrelated discovered host/project skill documents; bundled skills are off. The task prompt invokes `$name` without duplicating the skill body. Existing repository content is never overwritten. Post-launch SHA validation and cleanup happen before staging; unexpected changes fail the execution and retain residual evidence. `skill_loaded` audit events contain only name, SHA and native/injected mode. Claude uses the same checked instruction bytes as an explicit prompt addition, pending its authentication gate.

A supported MCP registry entry is:

```json
{
  "name": "factoryfiles",
  "manifest": {
    "transport": "stdio",
    "argv": ["python3", "-m", "adf_runtime_worker.scoped_mcp"],
    "trusted": true,
    "allowed_tools": ["read_marker"],
    "scope": {
      "contract": "adf.scoped-files.v1",
      "root": "$WORKTREE",
      "read_paths": ["marker.txt"],
      "max_bytes": 4096
    },
    "timeout_sec": 2
  }
}
```

Its typed tool mapping is `{ "permission": "read", "input_schema": { "type": "object", "properties": { "path": { "type": "string" } }, "additionalProperties": false }, "provider_mappings": { "codex": ["mcp__factoryfiles__read_marker"] } }`. The immutable definition name is the fallback MCP name; an explicit manifest name takes precedence. Server names must be unique and unambiguous.

`read_marker` reads the single approved file by default; `read_file` requires an explicit approved `path`. Exact read paths contain no globs, traversal, credential/config names or symlinks. The worker launches its installed owned server with isolated Python `-I -m`; project modules, `sitecustomize` and Python environment paths cannot replace it. The owned server uses held directory descriptors and `O_NOFOLLOW` on each component, regular-file and single-link inode checks, bounded reads and an OS per-tool deadline. Codex receives only selected `enabled_tools` plus bounded startup/tool timeouts. The server also rejects excluded tool calls and out-of-scope arguments independently. Its catalog includes a side-effect-free forbidden canary to verify native catalog filtering; the worker never enables that canary. No env lookup, network, authentication, mutation, resources or prompt methods are implemented.

Generic third-party MCP servers are not covered by this filesystem scope. `trusted: true` and a JSON `scope` alone do not confine an arbitrary subprocess; unsupported argv/contracts are refused until an independently verified implementation binds their access policy. This is an in-process worker capability, not another deployable service. The worker's existing user/group privilege limitations remain unchanged.
